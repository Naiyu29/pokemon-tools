# 選角截圖分析與對點計算

## 選角畫面辨識

選角畫面右側只有小圖示：sprite 剪影＋1–2 個屬性圖示＋性別。辨識流程：
1. 先由屬性組合縮小範圍，再用剪影輪廓確認（例：鋼＋幽＝賽富豪；岩＋惡＝班基拉斯）。
2. 每隻標註辨識信心；信心中等以下要在回覆裡明講「以實際選角畫面為準」。
3. 對手配置查 `data/threats.js` 有無現成；沒有的用常見標準配置推估（標註）。

## 計算流程（一個 Bash 回合完成，求快）

寫一段 node inline script 用 repo 的 @smogon/calc：
- 我方六隻從 `data/my-team.js` 載入；Mega 噴火龍用 overrides
  （baseStats 78/104/78/159/115/100、types Fire/Flying、ability Drought）。
- Field：`{gameType:'Doubles', weather:<場上天氣>}`；單打問題就不帶 gameType（無範圍打折）。
- 只算關鍵對位（每隻對手 2–3 招），不要全矩陣——對戰中求速度。
- 速度用 `pokemon.rawStats.spe`，圍巾 ×1.5、葉綠素晴天 ×2、順風 ×2 另列。

## 選 4 與首發的評分邏輯（規則式）

依序考慮，衝突時前面優先：
1. **特性剋制硬規則**：對面有不屈之心/爭強好勝 → 威嚇者降權；
   對面有金身（賽富豪）→ 依賴變化招者（劇毒/哈欠/拋下狠話）降權；
   對面有天氣特性（沙暴/垂滴）→ 評估天氣戰（登場特性先發動、Mega 日照在行動階段
   觸發所以首回合晴天蓋沙暴；之後誰後進場誰的天氣生效）。
2. **死亡對位**：被對面確1且無先手優勢的，進場需要護航；我方能確1對面的加分。
3. **速度**：比對面關鍵點快（含圍巾/天氣加成）加分；對面可能順風/欺騙空間時準備反制
  （空間局把最慢的棋升值）。
4. 產出：選 4＋首發 2＋後備 2、每個不選的一句理由、2–3 條戰場紀律
  （「X 與 Y 永不同場裸站」這類可背的規則）、關鍵數字表（確1/亂1 標記）。

## 辨識後回傳工具預填連結（M3 半自動流程）

辨識出對手後（不論是選角畫面或對戰截圖），回覆**最前面**附一條預填連結，
點開網頁工具即完成輸入、直接跳到推薦頁：

```
https://naiyu29.github.io/pokemon-tools/?foes=<id1>,<id2>,...&mode=doubles
```

- `foes`：對手英文名的 id——**小寫、去掉所有空格/連字號/符號**
  （Iron Hands→`ironhands`、Charizard-Mega-Y→`charizardmegay`、
  Ogerpon-Wellspring→`ogerponwellspring`、Urshifu-Rapid-Strike→`urshifurapidstrike`）。
  形態要寫完整形態名，不要只寫基礎名。最多 6 隻，逗號分隔。
- `mode`：`singles` 或 `doubles`（依截圖判斷；看不出來就依使用者說的模式）。
- `weather`（選用）：`Sun`/`Rain`/`Sand`/`Snow`——只在確定場上有天氣時帶
  （例：對面有班基拉斯先預設 Sand 不一定對，寧可不帶讓工具依特性自動提示）。
- 參數只在開啟當下生效一次，之後使用者可自由增刪；查無此名的 id
  工具會顯示「帶入失敗」提示，所以辨識信心低的隻也可以照放，並在回覆註明。
- 定位：這條流程約需 1–2 分鐘，**賽前 90 秒選角來不及**；適合賽後覆盤、
  遇到重複隊伍的預研。對戰中請使用者直接在工具內手動搜尋。

## 端上截圖辨識（M4，使用者自助、零 token）

工具內建「📷 截圖辨識」（對手分頁），兩個入口：
1. **分享**：Android 遊戲截圖 → 分享 → 選 Champions 工具（需已「加入主畫面」安裝 PWA）。
2. **選圖**：工具內按「截圖辨識」→ 從相簿挑圖。

點截圖上的寶可夢圖示 → 端上樣板比對（16×16 色塊＋剪影 IoU，毫秒級、不連網）
→ top-5 候選點一下加入對手。剪影圖示只比形狀、信心較低。

**與 Claude 流程的分工**：使用者先自助辨識（零成本）；認不出、要配置推估、
要選 4 建議時才貼截圖給 Claude（本檔上面的流程）。Claude 回預填連結的流程不變。

**維護**：描述子庫 `data/sprite-index.bin` 由 `npm run build:sprites` 產生
（抓 PokeAPI HOME 渲染圖，需網路），只在圖鑑加新形態時才需要重跑；
跑完要 `npm run build` 把 bin 複製進 docs/。準確率驗證：`npm run test:recognizer`。
若使用者回報真實遊戲截圖認不準（遊戲圖示風格與 HOME 渲染差太多），
解法是把真截圖裁出的圖示存成樣板重建庫，不要改比對演算法。
